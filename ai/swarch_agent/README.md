# swarch_agent

The service for SWArch-level capabilities. A Software Architecture model (a `.swarch` file) is the
model a person writes about their project; this service works with that model. Today it has one
capability: turning a Software Architecture model into a PIM (Platform-Independent Model), the
model every platform's transformation starts from.

It is plain Python. The transformation itself runs in `execution_agent`'s JVM, and the model check in
`validator_agent`'s.

## What it does, and how

`POST /pim` with the model's XMI text:

1. **Check.** `validator_agent`'s `/validate/swarch` runs the real EMF check. An invalid model is
   refused with its issues; nothing runs.
2. **Read the transformation.** The SWArch-to-PIM transformation is an `.atl` source file at
   `SWARCH2PIM_ATL_PATH`. It is read on every request, so replacing the file takes effect on the next
   one, with no restart.
3. **Run it.** `execution_agent`'s `/execute/atl/swarch` compiles that source and runs it on the
   model, and the PIM it produces is returned.

In Docker, `SWARCH2PIM_ATL_PATH` names the engine's own transformation inside its folder, which is
bind-mounted read-only (see `ai/CLAUDE.md`'s third exception). The folder is mounted rather than the
single file, so a replaced file is seen at once. The PIM is exactly what the engine's own SWArch-to-PIM step
produces for the same model; `main/`'s executor tests check that byte for byte on the engine's
example models.

## Who calls it

Its first caller is the pipeline generator, for platforms published from integration runs, which
need a PIM from the person's model before their own transformation and template can run.

## What a replacement transformation must look like

It must read the model under the name `SWArchMM` and declare its output with a
`create OUT : <Name> from IN : SWArchMM;` line: the engine binds the input model to that name, and
the output name is read from that line. A transformation that names its input otherwise is refused
with a message saying so.

## Why it owns the transformation as a file

The current SWArch-to-PIM transformation is expected to be improved, possibly regenerated by an
LLM, and the transformation may one day be generated inside the pipeline generator. Keeping it as
a source file that this service reads, and `execution_agent` compiles at run time, means an improved
transformation is a file swap: no Java change, no rebuild of the engine, no change to any caller.

## Where future SWArch capabilities go

A plain-language description turned into a Software Architecture model, by an LLM, is a planned
capability at this same model level. It belongs here as its own sibling module (a `generation.py`
next to `conversion.py`), following `pim_agent`'s one-service-per-model-level layout, and moves to a
separate service only if it ever needs a different runtime. A generator that writes a new
SWArch-to-PIM transformation is a different job (writing a transformation, like `atl_agent` does)
and would be its own service; this one would simply run what it produces.

## API

| Endpoint | Purpose |
|---|---|
| `GET /health` | Used by the Dockerfile's `HEALTHCHECK`. |
| `POST /pim` | Body: `content` (the model's XMI text). Returns `pim` (XMI text). |

| Outcome | HTTP status |
|---|---|
| The model was turned into a PIM | `200` |
| The model fails the EMF check (`detail.issues` lists severity and message for each problem) | `422` |
| The transformation ran and failed: it would not compile, or failed on this model. `detail.message` says so; the reason is in the service log, since the engine's own message can name temporary files. | `422` |
| `content` over `SWARCH_MAX_MODEL_BYTES`, or empty | `413`, `422` |
| The transformation file is missing or empty, or `execution_agent` answered in a way this service does not expect | `500` |
| `validator_agent` or `execution_agent` unreachable or failing | `502` |

Callers use `clients/swarch_agent_client.py`, which raises `AgentServiceError` for the `422` cases.

## Configuration

| Variable | Meaning |
|---|---|
| `SWARCH2PIM_ATL_PATH` | The SWArch-to-PIM transformation's `.atl` source. Unset, the engine's own file in this checkout. |
| `VALIDATOR_AGENT_URL`, `EXECUTION_AGENT_URL` | The services it calls. |
| `SWARCH_MAX_MODEL_BYTES` | The largest model accepted, in bytes. |

## Local development

```
cd ai/swarch_agent
pip install -r requirements.txt
uvicorn main:app --reload --port 8110
```

`pytest` runs the suite with both sibling services mocked.
